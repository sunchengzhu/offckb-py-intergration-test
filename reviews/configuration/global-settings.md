# 全局设置用例评审

评审范围：查看当前开发环境、选择下次使用的 CKB 版本，以及管理代理和独立用户环境
接口依据：`@offckb/cli@0.4.13`（`1551ef9`），并对照开发版 `0.5.0`（`b03577c`）的共同接口。

## 接口说明

- 输入：`config list`、`config get/set ckb-version`、`config get/set/rm proxy`，以及不带版本或二进制覆盖参数的 `node`，可选后台运行。
- `ckb-version` 选择 OffCKB 管理的 CKB 版本；测试目标 OffCKB 自身的 release/develop 选择由测试工程的 `config/offckb.toml` 管理，两者不是同一项配置。
- 可观察结果：CLI 报告的配置文件位置与有效设置、隔离目录中的 `settings.json`、新 CLI 进程的读取结果，以及 node/miner 实际使用的二进制。
- `config` 当前在日志中报告设置；JSON 模式 stdout 是通用完成结果，设置日志位于 stderr。这里不约定不存在的 stdout `settings` 或 `value` 字段，也不冻结日志排版。
- 版本应用场景预备真实、可运行且版本可核对的本地 CKB，放在隔离目录的对应托管位置，不触发下载。默认启动及版本选择场景让 OffCKB 自行选择已准备的托管二进制，其余节点场景可显式使用 `--binary-path`。
- 代理设置用不含凭据的本地 URL；本轮验证读写和删除，不据此宣称下载流量已通过代理。
- 全局设置属于用户环境，不以项目目录划分。两套环境使用测试拥有的不同 HOME/XDG 等根目录，不把在两个项目间切换误写成产品支持每项目独立配置。
- 优先验证查看设置和选择版本后真正生效；损坏文件及独立环境串用等补充保护不先于项目创建、部署和调用。

## 待评审用例

| 用例 | 场景 | 预期结果 | 防止的问题 | 优先级 |
| --- | --- | --- | --- | --- |
| `CFG-01` | 用户刚安装 OffCKB，想知道当前默认 CKB 版本、代理及配置保存位置，执行 `config list` 和相应的 `config get` | 命令成功；报告的设置文件及配置、数据、缓存路径均属于该隔离环境；CKB 版本与所安装包的默认版本一致，代理未设置；读取配置不启动节点 | 初次读取依赖开发者已有设置，或默认路径落到真实用户目录 | P1 |
| `CFG-02` | 用户要在指定 CKB 版本上开发，通过 `config set ckb-version v<version>` 选择一个已在本地准备、不同于包默认值的版本；在新进程查看配置后执行 `node`，不传版本位置参数或 `--binary-path` | 设置成功并持久化为去除前导 `v` 的版本；新进程读取值一致；node/miner 使用所选版本的本地二进制，其实际版本相符且 devnet 就绪；原有其他设置保留 | 设置只影响当前进程、版本规范化错误，或显示所选版本但实际仍启动默认二进制 | P0 |
| `CFG-03` | 用户配置本地代理供后续下载使用，用 `config get proxy` 确认；不再需要代理时执行 `config rm proxy`，期间保留自己选择的 CKB 版本 | 代理的协议、主机、端口正确持久化和读取；删除后新进程明确报告未设置代理；整个过程不改变原 CKB 设置及其他已有设置 | 代理只写不读、删除无效，或代理操作覆盖其他用户配置 | P1 |
| `CFG-04` | 用户修改已有配置时输错版本或代理地址，或者漏写值、写错配置项与操作 | 每次均非零失败并说明输入错误；设置文件保持原样，新进程仍读到原有效值 | 参数校验失败却保存部分修改，或错误请求静默重置已有设置 | P1 |
| `CFG-05` | 用户分别在两套独立用户环境中开发，设置了不同的 CKB 版本和代理；切换环境读取设置，并只修改其中一套 | 每个进程只读写当前环境的设置文件；A 的修改和删除正确持久化，B 的文件与有效设置不变；报告的根目录分别属于 A、B | 全局缓存或路径解析使两套开发环境串用配置，修改一套环境影响另一套 | P1 |
| `CFG-06` | 用户修改 CKB 版本或代理时，原设置文件已损坏，或没有读取、写入权限；分别在隔离环境中执行合法的 `config set` | 命令非零失败并明确报告读取或保存错误，不报告保存成功；原文件保持原样，读取失败时不得用默认配置覆盖旧设置 | 配置保存失败仍报告成功，或损坏设置被默认值覆盖而丢失恢复机会 | P1 |

## 使用边界

- `CFG-06` 的失败保护作为 release/develop 的共同验收要求。这里只约束修改设置；单独执行只读 `config get/list` 时是否允许回退默认值，不在本行约定。

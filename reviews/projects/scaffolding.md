# 项目创建与运行用例评审

评审范围：创建第一个合约项目，按项目说明完成构建、部署和调用，并保护已有项目
接口依据：`@offckb/cli@0.4.13`（`1551ef9`），并对照开发版 `0.5.0`（`b03577c`）的共同接口。

## 使用场景与验证边界

- 用户可以从默认示例开始，也可以指定自己的项目名、合约名和目标位置。创建成功后，应能按生成项目的说明继续构建、部署和运行示例。
- 默认创建保留依赖安装与 Git 初始化；用户主动选择手动安装或暂不使用 Git 时，才使用 `--no-install`、`--no-git`。
- 为固定选择，自动化可使用 `--no-interactive --language typescript --manager pnpm`；这不代表普通用户必须记住这些参数，也不宣称已经覆盖问答界面。
- 从产品源码目录之外调用隔离安装的 CLI，项目生成在独立临时目录；模板来自安装包。目标路径和名称的实际效果必须核对，不能只判断创建命令成功。
- 本地 CKB/debugger 使用真实可运行工具。默认创建的依赖、Git 及包管理器预先准备；下载使用明确 marker，外部服务不可用与产品创建失败分开判断。
- 生成的原有 build/deploy/test scripts 必须可用，不由测试改写脚本来绕过错误。隔离 CLI 通过 `PATH` 提供；签名使用私钥文件或 `OFFCKB_PRIVATE_KEY`，不在参数和日志中暴露私钥。

## 执行边界

- 默认创建、用户选择手动安装、生成项目完整运行是正常使用场景；不能把构建、部署和调用统一后置到异常保护之后。
- 已有项目目录保护是核心场景；空目录、普通文件、符号链接等特殊目标的扩展组合另行评审，不在本轮主线中铺开。
- 这里只运行生成项目交付的 mock 测试并验证其可用性，不复制 OffCKB 源码中的内部 mock 断言。

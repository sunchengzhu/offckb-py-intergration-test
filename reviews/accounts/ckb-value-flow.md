# 账户与 CKB 价值流转用例评审

评审范围：纯 devnet 的内置账户、CKB 余额、充值、定额转账和余额清扫
源码版本：`develop@44ab81d`

## 接口说明

- 接口作用：让开发者发现 devnet 账户，并通过 CLI 完成可在链上验证的 CKB 价值流转。
- 输入：`accounts`、`balance --no-udt`、`deposit`、`transfer`、`transfer-all` 及私钥文件。
- 成功结果：返回有效地址和交易哈希；交易最终 committed；Indexer 追平后余额变化与交易输出一致。
- 失败结果：命令非零退出、不返回成功交易哈希，接收方状态保持不变。
- 不负责：Testnet faucet、Mainnet、fork 资金来源和私钥明文命令行参数。

## 待评审用例

| 用例 | 场景 | 预期结果 | 防止的问题 | 优先级 |
| --- | --- | --- | --- | --- |
| `CKB-01` | 在全新纯 devnet 且 Indexer 追平后执行 `accounts --json` | 返回 index 为 0–19 的 20 个唯一 devnet 地址，地址、lock args 与 lock script 相互一致；逐个 lock 查询都能找到 fresh genesis 分配的 42,000,000 CKB；默认结果和 stderr 均不包含任何私钥字段或私钥值 | 打包账户表、地址编码与 genesis 分配不一致，或普通账户查询意外泄露私钥 | P0 |
| `CKB-02` | 先通过 OffCKB 为内置账户发行 SUDT 并等待交易 committed、Indexer 追平，再分别执行普通 `balance` 和 `balance --no-udt` | 普通查询返回该 SUDT 的正确 kind、type args 和非零数量；`--no-udt` 返回空 `udt`；两次结果均包含正确命令、网络和地址，CKB 数值相等且与同一 lock 下无 type、无 data 的纯 CKB live cells 容量之和一致，不包含 UDT cell 占用的容量 | 空资产前置条件掩盖余额发现失败或 `--no-udt` 参数被忽略，把代币 cell 占用容量误报为纯 CKB 余额，或单位换算错误 | P0 |
| `CKB-03` | 记录一个新接收地址的余额后，在 devnet 执行定额 `deposit` | 返回格式正确的交易哈希；交易最终 committed；Indexer 追平后接收方余额精确增加请求的 CKB 数量 | 命令只返回哈希但交易未上链，或充值金额和单位错误 | P0 |
| `CKB-04` | 使用非默认账户的受限权限私钥文件，从该已充值账户向另一地址执行定额 `transfer` | JSON 结果中的发送信息与输入一致；交易最终 committed，输入属于指定发送账户；接收方精确增加转账额，指定发送方减少转账额及链上实际手续费；命令记录中不出现私钥内容 | 忽略私钥文件而使用默认账户、私钥泄漏，或 CLI 成功但价值没有按预期转移 | P0 |
| `CKB-05` | 为一个临时账户充值后，通过私钥文件执行 `transfer-all` | 交易最终 committed；接收方增加“发送前全部余额减去 0.001 CKB”，发送账户不再有可花费 CKB cell | 清扫遗漏部分余额、手续费预留错误，或生成无法提交的输出 | P1 |
| `CKB-06` | 使用不存在或内容非法的私钥文件执行转账 | 命令非零退出且没有成功结果；不提交交易，目标地址余额保持不变，错误消息不回显私钥内容 | 凭据错误仍被当作成功，或敏感凭据进入日志 | P1 |
| `CKB-07` | 使用格式有效但没有资金的临时私钥执行转账 | 命令非零退出且不返回交易哈希；目标地址余额保持不变，后续正常交易不受影响 | 余额不足被误报为提交成功，或失败交易污染后续状态 | P1 |

## 本轮需要确认

- 首期只通过 `--privkey-file` 验证秘密输入主流程；`OFFCKB_PRIVATE_KEY` 作为等价入口留给后续兼容矩阵。
- 请确认 `CKB-01` 至 `CKB-07` 是否构成首期 CKB 价值流转验收范围。

# 合约交易调试用例评审

评审范围：用户通过交易哈希定位自己的合约执行问题，无需手工准备 debugger 输入
接口依据：`@offckb/cli@0.4.13`（`1551ef9`），并对照开发版 `0.5.0`（`b03577c`）的共同接口。

## 使用场景与验证边界

- 入口：`offckb debug --tx-hash <hash> --network devnet`；只查看一个脚本时增加 `--single-script 'input[0].lock'`。交易哈希使用 `--tx-hash` 传入。
- 使用真实 devnet、预备的本地 native `ckb-debugger` 和可产生稳定诊断的小型合约。故障必须来自合约执行，不能用格式错误的 RPC 请求替代。
- 观察实际提交的交易、OffCKB 生成的调试材料和 debugger 诊断是否对应；不替 OffCKB 手工补齐输入 cell 或依赖，不另行测试虚拟机规则和 cycle 精确数值。
- 被提交阶段直接拒绝的交易可能查不到 `get_transaction` 状态；以该次提交的明确拒绝、实际交易内容及调试结果核对。成功提交的对照交易仍须等待 committed。
- 这里使用普通文本调试输出；debugger 的脚本运行结果与 CLI 命令退出码分开理解，不能把已知失败脚本当作必须“执行成功”的合约，也不据此声称 `debug --json` 的输出契约已验证。

## 待评审用例

| 用例 | 场景 | 预期结果 | 防止的问题 | 优先级 |
| --- | --- | --- | --- | --- |
| `DBG-01` | 用户的项目通过 OffCKB proxy 提交一笔调用自己合约的交易，因已知的合约错误被拒绝；随后用该交易哈希执行 `offckb debug --tx-hash <hash> --network devnet` | OffCKB 找到刚才失败的实际交易，补齐其真实输入和依赖并完成调试；输出能定位对应脚本并显示该样例预期的诊断标识及失败结果，用户无需自己构造 debugger 交易文件 | 交易失败后只有 RPC 报错，OffCKB 丢失交易、取错上下文或仅启动 debugger 却无法帮助定位合约问题 | P0 |
| `DBG-02` | 用户已有一笔直接提交到本地 CKB、已确认但未被 proxy 缓存的交易，只想检查其中一个脚本，使用 `debug --tx-hash <hash> --single-script 'input[0].lock' --network devnet` | OffCKB 从所选本地链找到交易并完成指定脚本调试；诊断对应目标脚本，不执行同笔交易中另一个带不同可识别输出的脚本，用户无需重新通过 proxy 提交交易 | 调试只能处理缓存交易，或忽略脚本选择而输出无关结果 | P1 |

# 开发链启停与状态用例评审

评审范围：启动本地链开始开发、后台运行、结束后继续开发，以及保留配置重置数据或完整重置环境
接口依据：`@offckb/cli@0.4.13`（`1551ef9`），并对照开发版 `0.5.0`（`b03577c`）检查清理行为差异。

## 接口说明

- 接口作用：使用指定的本地 CKB 二进制管理一套可用、可停止且状态边界明确的开发链。
- 输入：`node`、可选的 `--daemon` 与 `--binary-path`、`node stop`、`devnet info`、`clean` 和 `clean -d`。
- 成功结果：node、miner、Indexer 和 RPC proxy 按阶段就绪；PID、端口、配置及链数据与命令结果一致。
- 失败结果：明确非零退出，不误报 ready，不遗留本次启动的后台进程或运行中 PID。
- 不负责：公共网络、完整 fork 流程、动态端口、并行 devnet 和全屏状态界面。
- 所有节点、用于冲突检查的进程、PID 文件及保护目录均由本次测试创建；不得使用真实开发者进程或目录。端口冲突覆盖必要监听端口，包括 direct RPC 和 proxy，避免只检查已经能正常回答 CKB RPC 的另一节点。
- 普通重启和清理后的启动沿用正常 CLI 流程；观察前不得由测试重建配置或删除 PID。组件退出和端口释放在截止时间内轮询，兜底清理只在判定产品结果之后执行。
- 首先关注用户能启动、连接、停止、继续开发和重置实验。`NODE-13` 覆盖默认前台用法，`NODE-01`、`NODE-04` 覆盖用户主动选择后台运行；不能仅因测试通常使用 daemon 就省略前台用法。

## 待评审用例

| 用例 | 场景 | 预期结果 | 防止的问题 | 优先级 |
| --- | --- | --- | --- | --- |
| `NODE-13` | 第一次使用 OffCKB，在已准备所需本地工具的新用户环境执行普通 `offckb node`，不指定 CKB 版本、二进制路径或 daemon；开发结束后在前台按 Ctrl+C | OffCKB 使用该包的默认 CKB 版本自行初始化开发链，提供可用的连接地址；节点可查询并持续产块；中断后所属 node、miner、proxy 退出并释放端口，再次执行相同命令可正常启动 | 基础上手命令依赖测试覆盖参数才能运行，或前台退出后遗留服务阻碍下一次开发 | P0 |
| `NODE-01` | 在没有 OffCKB 配置或托管二进制的全新隔离用户目录中，通过安装后的 CLI 执行 `node --daemon --binary-path`，不设置 `OFFCKB_CLI_PATH` | OffCKB 自行生成 node、miner 与 chain spec 配置；所属 node 和 miner 进程使用传入的本地 CKB 路径；命令只在 direct RPC 与 proxy RPC 都通过真实节点健康检查后返回；JSON 包含 daemon PID、RPC、proxy、日志和 PID 文件位置，PID 状态为 running | 首次启动依赖测试预写配置、打包入口无法自启动、忽略 `--binary-path`，或端口刚打开就误报 ready | P0 |
| `NODE-02` | daemon 启动完成后持续观察节点、miner 和 Indexer | tip 在截止时间内增长；Indexer 最终追平节点；`devnet info --json` 报告 `kind: pure-devnet`、`ready: true`、`indexerReady: true` 和 `indexerLag: "0"`，且报告的 RPC 地址与实际一致 | RPC 能连接但 miner 不产块，或余额与 cell 查询建立在落后的 Indexer 上 | P0 |
| `NODE-03` | 用户忘记后台开发链已经启动，再次对同一环境执行 `node --daemon` | 第二次启动明确非零失败并说明已有服务，不覆盖原 PID 元数据、不启动第二组组件；原节点继续响应并产块 | 重复启动破坏用户正在使用的开发链，或错误提示无法说明如何继续 | P1 |
| `NODE-04` | 对健康运行的 daemon 执行 `node stop`，在任何测试兜底清理前观察结果 | 返回 `stopped: true` 及原 daemon PID；OffCKB 自行终止 node、miner、proxy 整个服务组，关闭相关监听端口并删除 PID 文件 | 只停止外层 CLI 而遗留组件或 PID 元数据，测试兜底清理掩盖停止失败 | P0 |
| `NODE-05` | daemon 已停止或从未启动时再次执行 `node stop` | 命令幂等地以 0 退出并返回 `stopped: false` 和明确原因；过期 PID 元数据被清理，且不向无关进程发送信号 | teardown 因重复停止失败，或 stale PID 导致错误杀进程 | P1 |
| `NODE-06` | 用户结束开发前保存了自定义 node/miner 配置并完成一笔交易，通过 `node stop` 停止后台链；下次在同一用户环境用同一本地 CKB 启动继续开发 | 非默认配置保留；genesis hash 保持不变，旧交易仍为 committed，重启后的 tip 沿原链继续增长 | 普通重启静默重置配置或链数据，丢失开发状态 | P0 |
| `NODE-07` | 隔离 devnet 已有非默认配置和已提交交易，停止后执行 `clean -d`，再使用同一本地二进制启动；devnet 根目录之外另有测试拥有的文件 | chain data 被删除，`ckb.toml`、miner 配置和 chain spec 保留；重启使用相同 genesis 重建链，旧交易不再 committed；全局设置、托管二进制和根目录外的文件不变 | 仅重置链数据却丢失配置或误删目录外内容，或数据库没有真正清空 | P0 |
| `NODE-08` | 隔离 devnet 已有非默认配置、已提交交易和根目录内的调试缓存，停止后执行完整 `clean`，再使用同一本地二进制启动；根目录外另有测试拥有的文件 | 整个 devnet 根目录被删除；重启从随包默认文件初始化，原配置改动、旧交易状态和调试缓存不再保留；全局设置、托管二进制和根目录外的文件不变 | 完整清理留下旧状态，或删除范围越过 devnet 而损坏其他用户数据 | P0 |
| `NODE-09` | 用户为开发链指定了错误或无法运行的本地 CKB 路径，看到失败后改用有效路径重新执行启动 | 首次启动在截止时间内非零失败并给出可操作错误，不留下本次启动的 daemon、node、miner、proxy、PID 文件或监听端口；有效重试正常就绪 | 用户修正路径后仍被上次失败遗留的进程或状态阻塞 | P1 |
| `NODE-10` | 隔离环境中的 daemon PID 元数据指向一个仍存活、但不是 OffCKB daemon 的测试进程时，执行 `node stop` | 命令非零拒绝停止并指出进程身份不符；目标进程持续存活且未收到终止信号，原 PID 元数据保持不变 | PID 被复用或元数据错误时，OffCKB 杀死无关进程 | P1 |
| `NODE-11` | 用户启动开发链时所需端口已被另一个本地服务占用，停止冲突服务后重试；占用者由测试创建 | 首次启动在截止时间内非零失败，不误报 ready；原监听进程继续服务，本次启动的组件和 PID 文件全部清理；释放端口后同一环境能够正常启动 | 端口冲突时误伤其他服务，或冲突解决后仍无法开始开发 | P1 |
| `NODE-12` | 用户想重置已做过交易的开发链，但忘记先停止后台节点，直接执行 `clean` 或 `clean -d` | 命令非零拒绝清理并提示先执行 `offckb node stop`；已有配置和交易状态不被删除，原组件持续正常运行 | 对运行中的数据库直接删除，造成开发状态损坏或服务异常 | P1 |

## 范围边界

- `NODE-12` 的运行中清理保护作为 release/develop 的共同验收要求；两种清理分别使用测试拥有的隔离开发链，不能触碰开发者的节点或数据。
- 默认前台场景预备包默认版本的真实 CKB，让 OffCKB 自行选择它；这不覆盖首次下载。Ctrl+C 可用等价的前台 SIGINT 验证进程行为，不能据此宣称覆盖全部 TTY 操作。
- 普通停止仍核验进程和端口已释放；错误 PID 的单独保护场景排在正常开发流程之后。
- `NODE-07` 只约定保留 node/miner/chain spec 配置和重建链数据，不冻结 devnet 根目录内其他缓存的去留。开发版清理关联 Fiber 状态的行为另行评审。
- `NODE-07`、`NODE-08` 中目录外保护对象均是隔离环境内的测试数据，不检查或触碰开发者真实目录。

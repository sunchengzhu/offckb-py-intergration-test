# Devnet 配置编辑用例评审

评审范围：用户调整开发链的日志与运行选项，重启后继续开发，并在输错设置时得到明确反馈
接口依据：`@offckb/cli@0.4.13`（`1551ef9`），并对照开发版 `0.5.0`（`b03577c`）的共同接口。

## 接口说明

- 输入：已初始化且停止的 devnet 中执行 `devnet config --set key=value`；同一命令可多次传入 `--set`。
- 可观察结果：`ckb.toml`、`ckb-miner.toml` 中的解析值与类型，正常启动后的服务行为，以及失败退出码和错误信息。
- 使用公开可编辑字段中的字符串、布尔和正整数代表值，例如 `ckb.logger.filter`、`ckb.logger.color`、`miner.client.poll_interval`。不把所有 TOML 键都视为该命令支持的输入。
- 成功保存可以重新排版 TOML；未修改字段按解析后的含义比较，不要求注释和空白逐字保留。输入校验失败则要求两份文件都没有写入；本轮不约定跨文件磁盘写入故障的事务回滚。
- 生效检查选用用户排障时会调整的日志级别，通过 `offckb logs node` 查看本次启动的新记录。只验证 OffCKB 保存并应用设置，不展开 RPC 请求大小或 CKB 参数边界矩阵。节点使用预备的本地二进制，保持固定端口串行执行。
- 非交互入口用于固定用户选择，交互编辑器的按键和视觉效果另行验收。配置编辑成功后通过正常停止、启动应用日志设置，不清空链来掩盖配置未生效。

## 待评审用例

| 用例 | 场景 | 预期结果 | 防止的问题 | 优先级 |
| --- | --- | --- | --- | --- |
| `DVCFG-01` | 用户停止开发链后，通过一次 `devnet config` 调整日志级别、是否输出到文件和 miner 的更新间隔，使用多项 `--set` 保存自己的选择 | 命令成功；两份 TOML 均可解析，指定字段的值及类型正确；未指定字段的含义保持不变，链数据和 chain spec 不变 | 只应用最后一个参数、把布尔或整数写成字符串，或编辑一个字段时丢失其他配置 | P1 |
| `DVCFG-02` | 用户排查开发链问题，将原为 `warn` 的日志级别通过 `devnet config --set ckb.logger.filter=info` 调高；正常重启后用 `offckb logs node` 查看启动信息，随后把级别调回 `warn` 并重启 | 每次设置都保存到 TOML；`info` 时能看到本次节点启动的 INFO 记录，调回 `warn` 后本次新记录不再包含 INFO；链仍可用且保留已有交易，过程中不需手工重写配置或清空数据 | 修改日志配置成功却看不到所需信息，或普通设置调整导致开发状态丢失 | P0 |
| `DVCFG-03` | 用户一次修改多个开发链选项，其中后面一项写错键名、值类型或格式，前面一项本来有效 | 每次均非零失败，错误能定位非法输入；`ckb.toml` 与 `ckb-miner.toml` 均保持原字节内容，没有保存前面的合法项；链数据不变 | 批量配置只修改一部分就报错，留下用户未确认的混合设置 | P1 |
| `DVCFG-04` | 在 devnet 尚未初始化、所需 TOML 文件缺失或原文件无法解析的隔离环境中，执行合法的 `devnet config --set` | 命令非零失败并说明缺失或解析问题；不静默初始化或用默认配置覆盖原文件，已有文件和数据保持原样 | 配置编辑意外创建另一套环境，或把用户可恢复的配置损坏变成覆盖丢失 | P1 |
| `DVCFG-05` | 用户在脚本或不支持终端交互的环境中误执行不带 `--set` 的 `devnet config` | 命令在截止时间内非零退出并说明需要终端交互或 `--set`；不等待不可见输入、不修改配置、不启动节点 | 自动化进入交互界面后挂起，或非交互失败仍修改配置 | P1 |

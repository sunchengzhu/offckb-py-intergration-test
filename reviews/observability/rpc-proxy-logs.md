# 连接与日志排障用例评审

评审范围：项目连接本地 RPC proxy，用户查看请求错误和合约日志，并为调试保留交易
接口依据：`@offckb/cli@0.4.13`（`1551ef9`），并对照开发版 `0.5.0`（`b03577c`）的共同接口。

## 使用场景与验证边界

- 用户把项目连到 OffCKB 提供的 proxy，以便操作本地链并在出错时找到请求、交易和脚本信息。
- 日志用例通过正常启动、请求及合约调用产生真实记录，不仅向文件写入几行文本再验证过滤器。
- 默认文本模式用于查看日志；JSON 模式只做等价的脚本读取补充。筛选依据是本次操作可识别的交易哈希或脚本标识，不冻结时间戳、颜色和排版。
- 按交易哈希调用 debugger 的完整流程见[合约交易调试](../contracts/debugging.md)。这里不把“缓存文件存在”视为调试功能已可用。

## 待评审用例

| 用例 | 场景 | 预期结果 | 防止的问题 | 优先级 |
| --- | --- | --- | --- | --- |
| `OBS-01` | 用户把开发项目的 RPC 地址改为 OffCKB proxy，查询节点信息、genesis 和 tip，并与该开发链 direct RPC 核对 | 两端属于同一节点和同一条本地链，查询结果有效；通过 proxy 发出的请求能在 RPC 日志中找到 | 项目连接了错误网络或无法使用 proxy，用户看到与本地开发链不一致的状态 | P1 |
| `OBS-02` | 用户的项目通过 proxy 成功提交一笔交易，随后根据交易哈希寻找此次操作的记录 | 交易 committed，返回哈希与实际交易一致；交易目录中对应 JSON 与所提交交易一致，RPC 日志能按该哈希找到提交事件 | 交易虽然成功，但用户无法找到对应记录供后续排障和调试 | P1 |
| `OBS-03` | 用户的项目发出了错误的 RPC 方法请求，通过 `offckb logs rpc` 查看原因，修正方法后再次查询 | 请求方收到明确的原始 JSON-RPC 错误，RPC 日志包含对应方法及错误信息；修正后的请求正常返回，proxy 持续可用 | 项目调用失败却没有可用诊断，或一次错误后必须重启开发环境 | P1 |
| `OBS-04` | 用户运行会输出唯一调试标识的合约后，用 `offckb logs script` 查找自己的脚本输出；并用 node、miner、rpc 日志及 `--grep`、`--tail` 缩小本次操作的排查范围 | script 只显示节点日志中的脚本记录并包含本次合约输出，miner/rpc 分别读取对应日志；筛选结果符合指定文本及行数限制；后台运行时也无需翻找内部目录即可查看 | 用户无法通过 OffCKB 找到自己的合约日志，或筛选读错目标而误导排查 | P0 |
| `OBS-05` | 通过 proxy 发送方法名中包含换行、制表符及其他控制字符的 JSON-RPC 请求 | 请求仍按上游语义完成；每个 proxy 事件保持单个物理行，控制字符被替换且不能伪造额外 request/error 记录；随后正常请求仍成功 | 不可信 RPC 内容伪造日志，破坏诊断结果或代理可用性 | P1 |

## 范围边界

- 基本日志查找和按交易哈希调试属于用户开发流程；日志注入、长期轮转和高并发压力属于补充保护，不能把全部诊断功能统一推迟。
- 日志跟随的长期运行、TUI 显示和交互按键另行验收。对 `--tail`、`--grep` 只选典型使用，不展开边界组合矩阵。
